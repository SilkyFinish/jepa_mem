# Full-History v1 分阶段训练与串行评测

`scripts/train_eval_stages.py --config /path/to/config.json` 使用同一组 GPU 串行运行训练阶段与 RMBench 评测。机器路径放在本地 JSON 或忽略的 `.local.env` 中。当前 put_back_block 计划为双 RTX 5090、v1 空间压缩、BF16、每卡 batch=2、梯度累积4次、全局 batch=16、完整 full50 数据和既有冻结特征缓存；200 epoch 共12,600次更新，在3,150/6,300/9,450/12,600步分别做20次rollout。没有按日期或时钟设置的训练截止点。

每段训练均保持 `--num-epochs 200 --max-steps 12600`，由 `--stop-after-step` 在指定优化器更新边界保存并正常退出。`--save-training-state` 在 `resume_state.pt` 保存权重、AdamW moments、scheduler、每rank的Python/NumPy/PyTorch/CUDA随机状态和采样位置，下一段加载完整状态。不能用阶段长度修改总学习率计划，也不能以普通权重文件代替完整续训。训练发现非有限loss/梯度、分布式进程异常或检查点不匹配时停止并保留现场。

每10 epoch（630步）定期保存，保留最新两个普通权重导出和四个50-epoch里程碑权重。最新完整恢复文件原子替换，不为每个里程碑额外保存多份优化器。调度器验证训练进程退出、阶段更新数和完整恢复状态后，才启动单卡策略服务与独立的模拟器环境。文件锁阻止同一输出目录重复调度；显式 `STOP` 文件或终止调度器会请求在更新边界保存停止。默认不会因日历时间而停止。

评测使用原生 `native_qpos`、原生500步episode上限（`--max-steps 0`）、从100000开始的专家可解种子筛选和训练数据中的固定整任务指令。每轮保存实际接受种子；确定性的seed/trial会话ID与固定策略seed让对应请求使用一致的动作初始随机噪声。客户端逐决策写 `progress.json`。v1服务显式使用126个历史块、BF16和4 GiB KV分配/暂存预算，不丢弃旧历史；训练历史最大81块与评测500步容量是不同限制。

普通任务失败按正常评测计入成功率，即使0/20也继续训练。模拟器/策略服务报错、非零退出、结果不完整或长时间无进展，记录为该轮评测异常；清理本轮评测进程后恢复下一段训练。服务启动检查上限为10分钟，评测无进展看门狗为20分钟，这些是故障检测，不是整个任务的时间截止点。异常时保留部分episode记录和traceback，不把部分结果冒充完整20次成绩。用户显式STOP不会被当成评测失败后忽略。

本机计划及结果位于HDD的 `runs/rmbench_put_back_block_v1_ep200_20261022/`。`config.json`/`plan.json`保存参数，`status.json`记录阶段、子进程和评测结果，`train/progress.json`记录训练进度，`train/resume_state.pt`用于完整恢复，每个阶段的独立attempt目录保留训练/服务/评测命令和日志。正式运行使用归档源码副本，避免后续工作区修改影响自动启动的下一段。具体PID和启动时间以该目录运行记录为准。
